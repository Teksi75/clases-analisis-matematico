5to año · Programación · Guía docente

Clase 1: instrucciones, algoritmos y errores

Guía para una primera clase real de 60 minutos con estudiantes que usan la computadora, pero no programaron antes. Acompaña el apunte clases/clase-01.html y deja Java, NetBeans y objetos para cuando dominen instrucciones y trazas.

Resultado esperado

Al cierre, cada estudiante debería poder distinguir programa, instrucción y algoritmo; ejecutar mentalmente una secuencia corta; detectar un error comparando estado esperado contra estado obtenido; y corregir una instrucción o su orden con justificación.

No evaluar sintaxis Java, variables, ciclos, condiciones, clases ni objetos en esta clase.

Preparación y diagnóstico inicial

Material

  • Apunte estudiantil impreso o abierto en pantalla.
  • Pizarrón para dibujar una grilla de 3 por 3.
  • Marcador o resaltador para posición y orientación.

Diagnóstico sin conceptos previos

Pedí: “Escribí tres pasos para que otra persona encuentre una botella en el aula”.

Buscá: si usan referencias ambiguas como “allá”, “eso”, “cerca”. No corrijas todavía: usalo para mostrar por qué programar exige precisión.

Sin tecnología

Si no hay computadoras, la clase funciona igual con papel, pizarrón y lectura de pasos. Es mejor una buena traza manual que abrir NetBeans sin base conceptual.

Plan contiguo de 60 minutos

Tiempo Foco Acción docente Evidencia de avance
0-5 Encuadre Decí que hoy no se programa en Java: se aprende a pensar instrucciones. Presentá el objetivo medible. Entienden que la meta es escribir, ejecutar y revisar pasos.
5-12 Diagnóstico cotidiano Usá la consigna de la botella. Marcá ambigüedades: “allá” depende del observador; “cerca” no define distancia. Nombran al menos una instrucción ambigua y una forma de hacerla más precisa.
12-20 Conceptos base Definí programa, instrucción y algoritmo con ejemplos breves. Aclaración: la computadora ejecuta instrucciones definidas, no intenciones. Diferencian una orden suelta de una secuencia ordenada.
20-30 Modelo de grilla Presentá coordenadas, orientación y comandos permitidos: avanzar y girar derecha. No agregues comandos no disponibles. Predicen qué cambia con cada comando: posición o dirección.
30-40 Ejemplo guiado Resolvé el recorrido a (3,2) mirando →. Hacé la traza paso a paso en voz alta. Siguen la traza y justifican por qué el estado final coincide.
40-48 Ejercicio 1 Dales intento individual, luego pista gradual. Recién después mostrás la solución. La mayoría llega a (2,3) mirando → o identifica dónde se desvió.
48-55 Ejercicio 2 Trabajá error como revisión normal: ejecutar, comparar, corregir. No lo presentes como “adivinar el error”. Detectan que el algoritmo sale de la grilla e indican que giró demasiado temprano.
55-58 Ejercicio 3 Transferencia rápida: si falta tiempo, pedir solo primeras dos instrucciones y estado parcial. Aplican la misma técnica a un inicio distinto.
58-60 Cierre Hacé preguntas de salida y decidí la próxima clase según evidencia, no por calendario. Respuestas permiten clasificar dominio: firme, parcial o insuficiente.

Guion didáctico y respuestas esperables

Programa

Decí: “Un programa es una lista de instrucciones para que la computadora haga una tarea”.

Respuesta novel: “Es una app”.

Retomá: “Una app contiene programas; hoy nos importa la lista de instrucciones que la hace funcionar”.

Instrucción

Decí: “Una instrucción es una orden precisa que se puede ejecutar”.

Respuesta novel: “Andá para allá”.

Retomá: “¿Dónde es allá? Cambiémoslo por coordenadas o pasos medibles”.

Algoritmo

Decí: “Un algoritmo es una secuencia ordenada de instrucciones”.

Respuesta novel: “Es cualquier lista”.

Retomá: “Debe apuntar a resolver un problema y el orden importa”.

Cuidá las analogías: sirven si marcás el límite. El robot de grilla es una representación para aprender precisión; no digas que programar “siempre es mover robots”.

Comandos exactos para toda la clase

  • avanzar: mueve una casilla hacia donde mira. Cambia la posición, no cambia la orientación.
  • girar derecha: gira 90 grados a la derecha. Cambia la orientación, no cambia la posición.

No aceptar “subir”, “ir a B”, “girar izquierda”, “avanzar dos” ni diagonales en las respuestas de esta clase. Si aparecen, traducirlas juntos a comandos permitidos.

Clave del ejemplo guiado

Inicio: (1,1), mira ↑. Final: (3,2), mira →.

  1. avanzar → (1,2), mira ↑.
  2. girar derecha → (1,2), mira →.
  3. avanzar → (2,2), mira →.
  4. avanzar → (3,2), mira →.

Chequeo: coincide posición y orientación. Si solo coincide la posición, todavía no cumple el estado final completo.

Claves de ejercicios del apunte

Ejercicio Respuesta correcta Observación docente
Ejercicio 1 avanzar, avanzar, girar derecha, avanzar. Termina en (2,3), mira →. Si giran después del primer avance, llegan a otra fila. Pedí traza, no corrección por intuición.
Ejercicio 2 No funciona: termina intentando salir hacia (4,1). Corrección válida: avanzar, girar derecha, avanzar, avanzar. El error está en el orden: girar al principio cambia el recorrido completo.
Ejercicio 3 Una solución: avanzar, avanzar, girar derecha, avanzar. Termina en (3,3), mira →. Aceptá soluciones equivalentes solo si respetan comandos y estado final.

Andamiaje durante los ejercicios

Primer apoyo

Preguntá: “¿Qué estado tengo ahora: posición y orientación?”. Evita dar la próxima instrucción.

Segundo apoyo

Marcá con el dedo o marcador dónde queda el robot después de una instrucción. Pedí que narren el cambio.

Tercer apoyo

Ofrecé dos opciones cerradas: “¿Ahora conviene cambiar posición con avanzar o dirección con girar derecha?”.

Rutas según ritmo

Si van más lento

  • Hacé solo ejemplo guiado, Ejercicio 1 y preguntas de salida.
  • Reducí Ejercicio 3 a: “escribí las primeras dos instrucciones y el estado parcial”.
  • Trabajá con tarjetas físicas de comandos.

Si van más rápido

  • Pedir otra solución para el Ejercicio 3 y comparar cantidad de pasos.
  • Preguntar qué comando faltaría para acortar recorridos, sin incorporarlo todavía.
  • Inventar un estado inicial y final nuevo dentro de la misma grilla.

Sin computadoras

  • Un estudiante hace de robot y otro lee instrucciones.
  • La clase observa si la instrucción es ejecutable o ambigua.
  • Registrar traza en el pizarrón como evidencia.

Preguntas de salida: respuestas esperadas

Pregunta Respuesta aceptable
¿Qué diferencia hay entre una instrucción y un algoritmo? Una instrucción es una orden precisa; un algoritmo es una secuencia ordenada de instrucciones para resolver una tarea.
¿Por qué una computadora no puede resolver una orden ambigua como “andá para allá”? Porque no interpreta intención ni contexto como una persona; necesita instrucciones definidas.
En el Ejercicio 2, ¿en qué paso aparece el error y cómo lo detectaste? El problema aparece desde el primer paso: girar derecha antes de avanzar cambia el camino. Se detecta haciendo la traza y comparando con el estado final.
¿Qué revisarías primero si un algoritmo no llega al estado final pedido? Revisaría paso a paso la posición y orientación después de cada instrucción, y compararía el resultado con el estado final pedido.

Criterio para la próxima clase

Avanzá a instrucciones en Java o NetBeans solo si la mayoría puede trazar secuencias cortas y explicar un error sin que se lo marques. Si no, dedicá la próxima clase a más algoritmos con comandos limitados y recién después pasá a código.

Objetos, clases Java y POO quedan para más adelante: introducirlos ahora mezclaría demasiadas ideas nuevas en una primera hora.
