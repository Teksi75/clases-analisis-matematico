Preparación del profesor principiante

Antes de mirar código, conviene separar conceptos. Si el profesor también aprende Java, esta secuencia reduce carga:

  1. Dato y variable: un nombre guarda un valor, por ejemplo int n1 = 7;.
  2. Tipo int: sirve para números enteros; no guarda texto ni decimales.
  3. Asignación vs igualdad: = guarda; == pregunta si dos valores son iguales.
  4. Boolean: una variable boolean guarda solo true o false. Sirve para recordar estados como adivino.
  5. Negación: !adivino se lee “no adivinó todavía”. Si adivino es false, entonces !adivino es true.
  6. Y lógico: && exige que dos condiciones sean verdaderas al mismo tiempo, por ejemplo “quedan intentos y no adivinó”.
  7. Salida y texto: System.out.println(...) muestra algo en pantalla. Dentro, "texto" + variable une texto con valores para armar un mensaje.
  8. Entrada: Scanner teclado = new Scanner(System.in); construye con new un lector llamado teclado; teclado.nextInt() llama un método para leer un entero.
  9. Azar: new Random() construye el generador; nextInt(100) + 1 da valores de 1 a 100.
  10. Comparaciones: <, >, <=, >= y == producen verdadero o falso.
  11. Bloques: las llaves { } dicen qué instrucciones pertenecen a un if, else o while.

Diagnóstico priorizado

1. Asociar el else al if correcto

Ejercicio 1 Ubicación: TP1-1, bloque derecho inferior. Certeza alta.

Fragmento fiel resumido: se ven dos if para máximo; el else queda pegado solo al segundo if.

if (nro1 > nro2 && nro1 > nro3) { ... nro1 ... }
if (nro2 > nro1 && nro2 > nro3) { ... nro2 ... }
else { ... nro3 ... }

Interpretación: Mercedes parece pensar en tres alternativas, pero Java no agrupa los dos if como una sola decisión. El else pertenece al if inmediatamente anterior.

Consecuencia: si nro1 es el mayor, puede imprimirse también que nro3 es el mayor, porque el segundo if es falso y dispara su else.

Microejemplo propuesto, no transcripción:

if (nro1 >= nro2 && nro1 >= nro3) {
    System.out.println("Mayor: " + nro1);
} else if (nro2 >= nro1 && nro2 >= nro3) {
    System.out.println("Mayor: " + nro2);
} else {
    System.out.println("Mayor: " + nro3);
}

Explicación simple: else if arma una cadena: Java prueba una condición; si es falsa, prueba la siguiente; si ninguna se cumple, ejecuta el else. Cuando una condición se cumple, ejecuta su bloque y omite las demás alternativas de esa cadena.

Probemos con valores concretos: supongamos que el usuario ingresa primero 5, después otro 5 y por último 2. Son valores elegidos para este ejemplo, no números tomados de las fotos. Quedan guardados así:

nro1 = 5;
nro2 = 5;
nro3 = 2;

En Java, la primera condición del microejemplo es:

if (nro1 >= nro2 && nro1 >= nro3)

Equivale a preguntar:

  • ¿5 es mayor o igual que 5? Sí, porque son iguales.
  • ¿5 es mayor o igual que 2? Sí, porque 5 es mayor.
  • && significa “y”: exige que ambas comparaciones sean verdaderas. En este caso, las dos lo son.

Por eso se ejecuta el bloque del primer if:

System.out.println("Mayor: " + nro1);

Esta instrucción muestra Mayor: 5, porque nro1 contiene 5. El + une el texto con el valor para formar el mensaje. No se ejecutan el else if ni el else de esta cadena.

¿Por qué usamos >= y no solo >? Porque buscamos el valor máximo, aunque aparezca más de una vez. 5 no es mayor que otro 5, pero sí es mayor o igual. Los dos primeros números empatan y el máximo sigue siendo 5.

Pregunta guía: “¿A cuál if se pega este else si no escribimos else if?” Respuesta esperada: “Al if anterior más cercano”.

2. Resolver máximo y mínimo sin ordenar

Ejercicio 1 Ubicación: TP1-1, bloque inferior izquierdo y derecho. Certeza alta para la estrategia de comparaciones; igualdad no cubierta en forma visible.

Fragmento fiel resumido: aparecen comparaciones estrictas como nro1 < nro2 && nro1 < nro3 y análogas.

Interpretación: la idea de comparar está bien encaminada, pero las comparaciones estrictas dejan casos sin decidir cuando dos números son iguales.

Consecuencia: cuando dos números empatan como máximos o mínimos, exigir que uno sea estrictamente mayor o menor que todos los demás puede dejar ese empate sin resolver.

Puente con el punto anterior: la sección 1 enseña una cadena else if para elegir una alternativa; acá usamos otra estrategia: iniciar minimo y maximo, y actualizarlos al revisar cada dato.

Un ejemplo nuevo, paso a paso: supongamos que el usuario ingresa 7, 3 y 9, en ese orden. Para concentrarnos en las comparaciones, representamos esos datos con asignaciones directas, sin repetir aquí la lectura por teclado:

int nro1 = 7;
int nro2 = 3;
int nro3 = 9;

Para aplicar esa estrategia, el microejemplo agrega estas dos líneas justo después de declarar los tres números:

int minimo = nro1;
    int maximo = nro1;

¿Qué significa la primera línea? No asignamos int a nro1. La línea se lee así:

  • int: la nueva variable guardará un número entero.
  • minimo: es el nombre de la nueva variable.
  • = nro1: copiá en ella el valor que ya tiene nro1, que en este ejemplo es 7.

En lenguaje cotidiano: “Creá una variable llamada minimo y empezá guardando el primer número ingresado”. La segunda línea hace lo mismo con otra variable, llamada maximo.

¿Por qué ambas empiezan en 7? Porque primero tomamos solamente el primer dato como referencia. Entre los números revisados hasta ese momento —solo el 7— es tanto el menor como el mayor. Al revisar los otros datos, actualizamos estas referencias si corresponde.

Con esas cinco declaraciones listas, revisamos los otros datos:

if (nro2 < minimo) minimo = nro2;
    if (nro3 < minimo) minimo = nro3;
    
    if (nro2 > maximo) maximo = nro2;
    if (nro3 > maximo) maximo = nro3;

El código equivale a preguntar, en este orden:

  1. nro2 < minimo: ¿3 es menor que 7? Sí: minimo = nro2; guarda 3 en minimo.
  2. nro3 < minimo: ¿9 es menor que 3? No: minimo sigue valiendo 3.
  3. nro2 > maximo: ¿3 es mayor que 7? No: maximo sigue valiendo 7.
  4. nro3 > maximo: ¿9 es mayor que 7? Sí: maximo = nro3; guarda 9 en maximo.

Resultado: mínimo 3 y máximo 9. No ordenamos los datos: conservamos el menor y el mayor encontrados. Si otro dato fuera igual al mínimo o al máximo guardado, no haría falta reemplazarlo: el valor ya sería correcto.

Copiar no es vincular: estas variables de tipo int guardan copias de los valores. Cambiar minimo o maximo no cambia nro1, que sigue valiendo 7; nro2 y nro3 siguen valiendo 3 y 9.

Pregunta guía: “Si maximo vale 7 y miro un 9, ¿qué debería pasar?” Respuesta esperada: “Actualizar maximo a 9”.

3. Nombres válidos y uso consistente de identificadores

Ejercicio 2 Ubicación: TP1-2, primeras líneas y condición del while. Lectura alta para nombres informales con n° y espacios; lectura probable para diferencias de mayúsculas/minúsculas.

Fragmento fiel resumido: aparecen nombres de cuaderno como n° de intentos, n° usuario y formas parecidas a Intentos. También se lee parecido a Random r = new Random(); y luego random.nextInt(100).

Interpretación: en una explicación manuscrita esos nombres pueden ser atajos comprensibles. En código Java literal, los identificadores no llevan espacios ni símbolo °, y Java distingue mayúsculas de minúsculas: intentos e Intentos serían nombres distintos. Las palabras clave también van en minúscula: while, if, else.

Consecuencia: si se crea una variable con un nombre, después debe usarse exactamente el mismo. Si se crea r, se usa r; si se crea intentos, no se mezcla con n° de Intentos.

Nombres válidos propuestos: intentos, numeroUsuario, secreto, adivino, r.

Random r = new Random();
int secreto = r.nextInt(100) + 1;
int intentos = 0;
int numeroUsuario = teclado.nextInt();

Explicación simple: el cuaderno puede decir “n° de intentos” para entender la idea; el programa ejecutable necesita un nombre sin espacios y repetirlo igual cada vez.

Pregunta guía: “¿Qué nombre exacto elegimos para el contador y cómo lo repetimos?” Respuesta esperada: “intentos, siempre escrito igual”.

4. Rango correcto para el número secreto

Ejercicio 2 Ubicación: TP1-2, generación del número. Lectura incierta sobre el + 1; sí se ve intención de usar nextInt(100).

Interpretación: la consigna pide del 1 al 100. En Java, nextInt(100) solo genera de 0 a 99; por eso se suma 1.

Microejemplo propuesto, usando el generador r creado en el ejemplo anterior:

int secreto = r.nextInt(100) + 1; // 1..100

Explicación simple: primero Java sortea 0..99. Al sumar 1, esos valores pasan a 1..100.

Pregunta guía: “Si nextInt(100) puede dar 0, ¿qué pasa cuando sumo 1?” Respuesta esperada: “El menor resultado pasa a ser 1”.

5. Evitar el punto y coma después del while

Ejercicio 2 Ubicación: TP1-2, línea del while. Lectura probable: parece haber un ; después de la condición.

Fragmento fiel resumido: la línea se parece a while (n° de intentos < 10); {.

Interpretación: si ese punto y coma está realmente ahí, Java interpreta que el while tiene cuerpo vacío; el bloque con llaves queda separado. Esta es una hipótesis de lectura sobre el signo visible, no una afirmación absoluta sobre el programa completo.

Consecuencia de esa hipótesis: el ciclo no repetiría las instrucciones esperadas como cuerpo del while; el problema es distinto del mensaje final o del contador.

Microejemplo propuesto:

while (intentos < 10 && !adivino) {
    // instrucciones que se repiten
}

Explicación simple: después de while (...) van llaves, no punto y coma, cuando queremos repetir varias instrucciones.

Pregunta guía: “¿Qué parte exacta queremos que se repita?” Respuesta esperada: “Pedir número, contar intento, comparar y mostrar pista”.

6. Política de conteo, salida del ciclo y final sin falsa derrota

Ejercicio 2 Ubicación: TP1-2, rama ganadora, incrementos y mensaje final. Certeza media: se ve una rama de acierto; no se ve una marca clara de salida del ciclo ni una variable booleana de corte.

Interpretación: conviene definir una política simple: cada intento entero válido cuenta una vez, incluido el intento ganador. Además, cuando se acierta, el ciclo debe dejar de pedir números. El chequeo final fotografiado se parece a > 10; bajo un ciclo normal intentos < 10 con incrementos de a uno, ese valor no se alcanza al salir por límite, por eso conviene evaluar !adivino al terminar.

Brecha visible de requisito: en la rama ganadora se ve un mensaje tipo “Adivinó”, pero no se ve una actualización como adivino = true ni un break. No afirmamos que no exista fuera de la foto; solo que no aparece en el fragmento fotografiado.

Consecuencia: si el contador solo aumenta en errores, un acierto no queda contado. Si el ciclo no mira !adivino, puede seguir pidiendo después de acertar.

Microejemplo propuesto:

while (intentos < 10 && !adivino) {
    int numeroUsuario = teclado.nextInt();
    intentos = intentos + 1;

    if (numeroUsuario == secreto) {
        adivino = true;
        System.out.println("Correcto. Intentos usados: " + intentos);
    } else if (numeroUsuario < secreto) {
        System.out.println("El secreto es mayor. Quedan " + (10 - intentos));
    } else {
        System.out.println("El secreto es menor. Quedan " + (10 - intentos));
    }
}

El contador en palabras: intentos = intentos + 1; equivale a decir: “Tomá la cantidad de intentos que llevabas, sumale uno y guardá el resultado en la misma variable”. Contamos después de leer la respuesta; luego comprobamos si acertó.

La repetición en palabras: while (intentos < 10 && !adivino) significa: “Mientras queden intentos y todavía no haya acertado, repetí el bloque”. adivino = true registra el acierto; así, la próxima comprobación impide otra vuelta.

Pregunta guía: “Si acierta en el décimo intento, ¿debe decir ‘sin intentos’?” Respuesta esperada: “No, porque ganó aunque haya usado el último”.

7. Pista desde la perspectiva correcta y restantes visibles

Ejercicio 2 Ubicación: TP1-2, ramas de comparación. Certeza alta sobre la intención de mensajes mayor/menor; certeza alta de que no se ve salida con cantidad restante en las ramas fotografiadas.

Interpretación: la consigna pide responder si el número a adivinar es mayor o menor que el introducido, además de informar los intentos que quedan. La frase debe hablar del secreto, no del intento aislado.

Brecha visible de requisito: en las ramas de “mayor” y “menor” no se ve un mensaje que calcule 10 - intentos. No afirmamos que no exista en otra hoja; solo que no aparece fotografiado.

Microejemplo propuesto:

if (numeroUsuario < secreto) {
    System.out.println("El número secreto es mayor. Quedan " + (10 - intentos));
} else if (numeroUsuario > secreto) {
    System.out.println("El número secreto es menor. Quedan " + (10 - intentos));
}

Pregunta guía: “Si Mercedes dice 30 y el secreto es 42, ¿qué pista ayuda y cuántos intentos quedan tras contar ese ingreso?” Respuesta esperada: “El secreto es mayor; si era el primer intento, quedan 9”.

8. Ejercicio de matrices: diferir, no descartar

Ejercicio 3 Ubicación: TP1-1, consigna; no hay solución fotografiada. Certeza alta sobre la consigna visible, sin evidencia de resolución.

Interpretación: la matriz requiere arreglos bidimensionales, ciclos anidados, dimensiones y azar. Es más complejo que máximo/mínimo y adivinar número.

Decisión docente: dejarlo para una etapa posterior, después de dominar variables, entrada, if, while, contador y Random.

Pregunta guía futura: “¿Qué cambia si tengo 5 filas y muchas columnas?” Respuesta esperada: “Necesito repetir por filas y por columnas”.

Trazas manuales y escenarios límite

Usá estas trazas antes de mostrar un programa completo. Fijan el comportamiento esperado.

Traza trabajada: secreto fijo 42, entradas 30 y 42

Estado inicial

secreto = 42, intentos = 0, adivino = false. La condición intentos < 10 && !adivino da verdadera.

Primera lectura

Mercedes ingresa 30. Antes de contar: intentos = 0. Después de intentos = intentos + 1: intentos = 1.

Primera comparación

30 == 42 es falso. 30 < 42 es verdadero, entonces la pista es “el secreto es mayor”. Quedan 10 - 1 = 9. adivino sigue en false.

Segunda vuelta

La condición vuelve a dar verdadera: 1 < 10 y !adivino es verdadero. Mercedes ingresa 42; luego el contador pasa a 2.

Acierto y salida

42 == 42 es verdadero. Se ejecuta adivino = true. Quedarían 10 - 2 = 8 intentos sin usar, pero ya no se piden más números porque la próxima condición usa !adivino, que ahora es falso.

Escenarios límite con secreto fijo 42

  1. Primer éxito: intento 1, ingresa 42 → cuenta 1, acierta, termina con mensaje de éxito.
  2. Intento bajo: intento 1, ingresa 30 → cuenta 1, no acierta, pista: “el secreto es mayor”, quedan 9.
  3. Intento alto: intento 2, ingresa 60 → cuenta 2, no acierta, pista: “el secreto es menor”, quedan 8.
  4. Décimo éxito: llega al intento 10, ingresa 42 → cuenta 10, acierta, no debe mostrar derrota.
  5. Diez fallos: después del intento 10 incorrecto quedan 0; se muestra derrota y no hay undécimo pedido.

Máximo y mínimo de tres números

  • Mayor primero: 9, 4, 2 → máximo 9, mínimo 2.
  • Mayor segundo: 4, 9, 2 → máximo 9, mínimo 2.
  • Mayor tercero: 4, 2, 9 → máximo 9, mínimo 2.
  • Igualdad: 5, 5, 2 → máximo 5, mínimo 2; 3, 3, 3 → máximo 3, mínimo 3.

Referencia docente opcional

No hace falta mostrar esto al inicio. Está para que el profesor tenga una forma completa y coherente si necesita contrastar microejemplos.

Recordatorio: esta referencia mantiene el supuesto de etapa: entradas enteras válidas. El programa es propuesto para lectura docente; no se afirma que haya sido compilado ni ejecutado.

Ver programa propuesto de adivinar número 
import java.util.Random;
import java.util.Scanner;

public class AdivinarNumero {
    public static void main(String[] args) {
        Scanner teclado = new Scanner(System.in);
        Random r = new Random();

        int secreto = r.nextInt(100) + 1;
        int intentos = 0;
        boolean adivino = false;

        while (intentos < 10 && !adivino) {
            System.out.println("Ingresá un número:");
            int numeroUsuario = teclado.nextInt();
            intentos = intentos + 1;

            if (numeroUsuario == secreto) {
                adivino = true;
                System.out.println("Correcto. Lo adivinaste en " + intentos + " intentos.");
            } else if (numeroUsuario < secreto) {
                System.out.println("El número secreto es mayor. Te quedan " + (10 - intentos) + " intentos.");
            } else {
                System.out.println("El número secreto es menor. Te quedan " + (10 - intentos) + " intentos.");
            }
        }

        if (!adivino) {
            System.out.println("Sin intentos. El número era " + secreto + ".");
        }

        teclado.close();
    }
}

Glosario mínimo para el profesor

  • Variable: nombre que guarda un valor.
  • int: tipo para enteros.
  • =: asigna un valor.
  • ==: compara igualdad.
  • boolean: tipo que solo guarda true o false.
  • !adivino: se lee “no adivinó”; niega el valor booleano.
  • &&: “y lógico”; las dos condiciones deben cumplirse.
  • System.out.println: método que muestra texto o valores en pantalla.
  • "texto" + variable: une texto con el valor de una variable para armar un mensaje.
  • Scanner: herramienta para leer entrada.
  • new: construye un objeto para poder usar sus métodos.
  • Método: acción que se llama con paréntesis, por ejemplo nextInt().
  • Random: herramienta para generar azar.
  • if/else: decisión entre caminos.
  • while: repetición mientras una condición sea verdadera.
  • Contador: variable que se actualiza para medir cantidad de pasos.
